## 5. 游戏日志确认与根因

【决策:2026-10-11】零云距离 / TSS 判据是本次已捕捉故障的直接原因。用户反馈关闭 TSS 后恢复;GPU 日志确认颜色在上采样阶段丢失。

### 5.1 丢失链路

以下为修复前源码与行号,保留作为故障证据;当前实现见 §6。

1. 云球包含相机且相机所在位置有云密度时,零抖动令第一步 `rayDist=0`。`Clouds.shader:675` 把首云距离记为 0,仍计算出非零云颜色。
2. `Clouds.shader:731` 直接输出该距离;0 同时也是未命中云的编码,命中状态发生歧义。
3. `Clouds.shader:867` 的 `freshDepth > 0` 将当前云判成无云;`:878` 对历史也采用正距离门控。故障帧中心原始运动矢量为 (-1.593, -5.758),虽有限却远超画幅,进一步令重投影出界。
4. 当前云无效、历史不可用时,TSS 走 `Clouds.shader:926`,输出全零 RGBA。关闭 TSS 时采用当前颜色与有效历史混合,保留当前云颜色。
5. `CloudReflectionRenderer.cs:198` 直接把原始云颜色绑定为合成输入,没有经过主相机的 TSS 判据,因此倒影仍可见。

故障批次远深度就绪、轨道淡入为 0,配置 / 实际材质密度、覆盖和高度上限相同;原始 RGB 已非零。因此该批次无需用材质漏同步、轨道淡出或雾遮挡解释。日志里的雾仍为开启状态;“关雾仍消失”来自用户先前反馈。

### 5.2 修复目标与剩余风险

- 分离真实命中和零距离的语义,保留相机云内的有效命中。若继续用正距离编码命中,距离须有可解释的正值下限;同时核对合成 / 雾的距离消费者。
- 零距离点不能直接作为运动矢量的投影锚点。当前代码 `reproj.xy / reproj.w` 未保护退化投影;需要稳定锚点或当前帧降级,防止巨大 / 非有限运动矢量。
- TSS 在历史不可用时应保留真实当前值。当前全零兜底还把无云的透射率 1 清成 0;日志已记录此现象,需覆盖不同合成模式。不能单用 alpha 推断有云,地表阴影也会改变它。
- 重定位计数为 318,最近变化仅约 2.4e-10m / 1e-9m/s;现有处理仍清历史。它可能放大历史不可用,但已有证据不支持把它当作本次直接原因;是否过滤应另行核对坐标与历史契约。

回归覆盖云内零距离、正距离云、无云透射率、TSS 开 / 关、历史清空、运动重投影及水面倒影,独立结果见 §6。游戏复验与微小重定位处理仍未完成。

## 6. 修复实施与验证

## 7. 开启 TSS 后轨道 2D 云异常

【决策:2026-10-11】用户反馈开启 TSS 后轨道 2D 云不能正常显示。检查实际日志与资源生命周期后,修复轨道路径依赖体积路径绑定深度的缺口。

### 7.1 证据与原因

- 最新游戏 `Player.log` 最后写入 2026-10-11 00:31:03,已加载 `build=2 shader=2`。帧 9536 等记录 `tss=True fade=1.000`,相机海拔 384134.6m,雾关闭;远深度就绪,配置 / 材质参数一致。纯轨道阶段体积 raymarch / TSS 整条跳过,旧诊断没有读取轨道颜色,不能仅凭该日志认定轨道 GPU 输出。
- `CloudRenderer` 切换 TSS 会改变云纹理尺寸,并据此重建共享 `lowResDepthTex`。原有 `DepthTex=lowResDepthTex` 只在体积绘制的 `orbitFade>=0.999` 早退之后执行。
- 高空纯轨道云跳过该绑定,随后 OrbitClouds 虽用新低清深度作为 Blit 输入,但 shader 实际读取的是独立 `DepthTex`,而不是 `_MainTex`。因此材质仍可能持有旧的、已释放 / 销毁的深度纹理;射线壳交点被无效深度错误判为遮挡,输出无云。
- TSS 开关是重建触发器;高空直接加载、分辨率变化也可能走到相同缺口。它不要求 Upscale pass 在轨道阶段运行。
- 独立 GPU 受控复现同一顺序:有效深度时原始轨道 RGB 为 (0.0588, 0.0784, 0.0980);释放旧深度并重建、保留旧绑定时 RGB 全零;显式绑定当前场景深度后恢复相同颜色。该证据来自正式 OrbitClouds pass 与受控绑定顺序,没有声称运行了完整游戏渲染器。

### 7.2 修复

- `CloudRenderer` 每层绘制轨道云前显式绑定 `DepthTex=combinedDepthTex`,使用本相机当前帧的场景深度;Blit 输入也改为该纹理。
- 轨道深度不再通过体积 raymarch 的绑定副作用取得,其分辨率不随 TSS 格网变化。云与 craft / 地形的遮挡判断继续保留。
- DevMode 日志升级 `build=3`,逐层增加 `orbitDepthSource`。纯轨道的 `skipped-volume` 摘要也记录此字段,该状态表示有意跳过体积绘制。
- 本轮行为修复位于 C#,shader 保持上一轮版本 2;部署时更新模组代码,并确保先前 shader 修复已部署。没有新增 RT、绘制 pass 或同步 GPU 回读。

### 7.3 验证与待验收

- `Volken.csproj` 完整编译:0 错误 / 4 警告。
- Unity 2022.3.62f3 / D3D11 GPU 回归 **94 通过 / 0 失败**,包含上一轮 58 项与本轮新增 36 项。新增用正式 OrbitClouds / Composite pass 验证旧深度故障复现、重新绑定恢复、纯轨道冷启动、TSS 反复开关、fade=0 / 0.5 / 1 的两种现有合成模式、前景遮挡、射线未命中与纯轨道日志深度源。两种模式按现有合成语义断言,TSS 切换后的结果保持一致。

## 10. Perlin–Worley 主形状与体积远景颗粒

> 本节保留 build=6 / shader=5 的实施与静态测试证据。用户后续反馈镜头运动抖动,本节的像素足迹过滤 / 瓦片退场已由 §11 替代;169 项旧验证未覆盖同一世界射线在不同 FOV / 朝向下的稳定性,不能证明该版本已验收。

### 10.1 原因与对照

- 最新用户游戏日志已加载 `build=5 shader=4`,轨道深度源为 scene。截图中的浮雕为 4、额外细节为 0;关闭轨道后体积云仍有颗粒,不是再次丢绑定或只由额外 albedo 造成。
- 原 shape / detail 均为多 octave Worley。Worley 本身适合细胞状细节与侵蚀,但同一类细胞起伏主导轮廓时,阈值和浮雕容易形成密集小团;此前过滤并没有改变可分辨的基本形状。

- 体积路径仍以 mip 0 查询 shape / detail,远处短波没有过滤。补 mip 后的中间版又出现周期格纹:最高几级 R8 mip 中很小的残余变化仍被密度阈值放大。最终版同时补瓦片退场,避免用微小周期变化驱动远景形状。

## 11. 镜头旋转 / 缩放抖动:固定世界场与时序权重修复

> 本节保留 build=7 / shader=6 的稳定性证据。用户后续截图显示成排纹理,并明确反馈画质退步;固定粗化与新主噪声已由 §12 撤回。固定格点的统一时序权重继续保留,170 项通过不能当作画质验收。

### 11.1 复现与原因

用户反馈 §10 版本在镜头转向 / 缩放时整个云层与画面持续抖动。重新读取游戏日志确认实际运行 `build=6 shader=5 shapeNoise=VolkenPerlinWorleyShape noiseMips=8/8`,不是旧资源回退;日志中的预设为 `2Dtest`,蓝噪声抖动为 0。

1. **密度场依赖镜头**:体积 raymarch 由 `ddx/ddy(viewDir)`、观察距离、TSS 格网倍率选择噪声 mip 并将小瓦片退到平均值;同一世界位置的密度随 FOV / 朝向 / 分辨率变化。这个变化发生在覆盖阈值之前,足以改变云命中和首个命中距离。光照与地表云影也使用同一视角过滤,可以扩大为整幅场景的明暗变化。
2. **轨道覆盖与浮雕依赖镜头**:壳点导数驱动 shape / detail mip、平均值退场和 stock 分布 mip,浮雕有限差分的世界步长也取像素足迹。镜头变化同时改变云边界、云内纹理和法线,已经超出纹理抗锯齿的作用。
3. **固定格点却轮换时序权重**:实际 Clouds 顶点 / 射线没有使用 `_SampleCell` 改变采样位置,每帧覆盖同一套低清格点;Upscale 却轮换新鲜格,在同一位置交替使用纯本帧和历史混合。独立输入证明仅切换相位就会产生最大 0.30 的通道变化。该逻辑不能产生额外空间样本。

源代码没有写入相机 transform 或 FOV。本次修复的是随镜头变化的云场、阴影和时序输出;用户看到的实际画面稳定性仍须进游戏复核。Perlin / Worley 的纹理生成本身具有种子确定性,此次根因在消费路径,继续换噪声种类不能解决这些耦合。

## 12. 画质回退:恢复旧体积云与轨道宏观覆盖

> 本节记录 build=8 / shader=7。用户后续确认有改善,但关闭轨道云后仍有密集颗粒;体积光照 / 重建已由 §13 接管。§12 的逐像素旧体积输出一致仅适用于该版本,不作为新光照积分的等价保证。

### 12.1 证据与原因

用户反馈“效果还不如以前”,截图中的局部云团出现明显成排纹理。读取游戏日志确认已经运行 `build=7 shader=6 shapeNoise=VolkenPerlinWorleyShape noiseMips=8/8`;`2Dtest` 在约 939 / 1792 / 1624km 高度、FOV 20° 下为纯轨道态,雾关闭。此时体积与 TSS 绘制已跳过,不能把成排纹理归因于正在运行的时序累积。之后 `Atmospheric` 的低空 / 79km 样本属于另一段测试,不用于判断截图预设。

使用真实缓存的 1024 cubemap、128³ 噪声和 `2Dtest` 换算后的参数,受控固定 seed=1337,复现了上一版的排队纹理。新 Perlin–Worley 主形状仍是短周期纹理,壳面读取单切片后被覆盖阈值与浮雕放大;固定 mip 1 / stock mip 2 只改变带宽,没有消除该结构,还改变了原预设细节。换回旧噪声能减弱规则排列,但继续以局部切片决定轨道覆盖仍有很重的细颗粒。

§11 解决了同一世界射线的镜头依赖与相位闪烁,没有证明云形好看。本次承认主噪声替换与固定粗化的画质回退,撤回这两项。问题不能简单归为 Worley 的固有缺陷:周期、频率、壳面表示和覆盖 / 浮雕共同决定最终结果。

### 12.2 源码修改

## 13. 纯体积远景颗粒:单段光照积分与输出重建

### 13.1 游戏证据与受控分离

用户确认 §12 有改善,随后截图关闭轨道云与 TSS,密集白色颗粒仍可见。新日志确认 `build=8 shader=7`、`2Dtest`、海拔约 1391.822km、FOV 20°、`fade=0 tss=False jitter=0 fog=False`,raw 为 1280×800,up 为 2560×1600;原始体积云已经有颜色和有效命中。剩余颗粒属于体积路径,不能继续用轨道浮雕或 TSS 历史解释。

固定 seed=1337、真实 128³ Worley / 1024 stock 缓存与预设输入,分别对照噪声 mip、FBM gain、视线步长和单段积分。当前高空视线步长最大约 386.6m;光线步长为 240m。原代码每段按 `density×step×transmittance` 直接累加云光,该段内 Beer 衰减只应用到后续段。厚样本因此贡献偏高,会放大密度变化形成的亮点。

640×400 的隔离对照中,缩小步长和修正单段积分都降低了高空亮点对比;单独噪声 mip 1 收益很小,mip 3 会使 25km 的平均覆盖从约 0.211 降到 0.091,并留下规则结构。因此没有继续粗化世界密度。单段积分也不能消除空间欠采样,最新版本在体积积分之后重建颜色与透射率。

### 13.2 最新实现

| 路径 | 处理 |
|---|---|
| Clouds 云光累加 | 新 `SegmentScatteringWeight` 对当前 Beer 函数在单段内解析积分。令 `τ=max(0,density×step×absorption)`,权重为 `amb+(1−amb)×(1−exp(−τ))/τ`;很小 τ 用二阶展开,避免除零 / 相减精度损失。保留原环境项和后续透射率公式 |
| Upscale 本帧颜色 | 新 `ReconstructCurrentCloud` 在世界像素尺寸超过 shape 噪声体素尺寸时,平滑启用 3×3 加权重建;RGB 与透射率用同一组权重,再进入原有时序 / 残影混合。强度由低清 RT 的像素尺寸、FOV 与云距离决定 |
| 遮挡与近处样本 | 相机位置命中、无命中、已在场景后方及已解析样本直接保留本帧。比较前先把场景 eye depth 换成射线米,拒绝位于当前场景之后的邻点;边界有效权重重新归一化 |
| 世界场与轨道 | 原 shape / detail、密度阈值、mip 0、云命中距离、光照 / 云影查询及轨道宏观覆盖保持。重建作用于积分后的输出,没有按 FOV / 朝向改变阈值前的密度场;真正反平铺与新过渡曲线仍未实施 |
| 版本 | `build=9 shader=8`,正常 `shapeNoise=VolkenWorleyFBM noiseMips=8/8`;本次 compute 无变化 |

解析权重解决的是单段内累加误差,不宣称整个离散步进与环境透射模型在任意步长下完全等价。空间重建会平滑远景短波明暗与细边缘,不能当作增加了真实射线样本或消除了底层周期。FOV 改变会改变输出像素的过滤范围,这是积分后重建;世界密度和中心命中仍须通过同一射线的稳定性检查。

### 16.1 修复前取证与归因

读取 `<USERPROFILE>/AppData/LocalLow/Jundroo/SimpleRockets 2/Player.log`,最后写入时间为 2026-10-14 02:20:43,运行 `build=11 shader=10`。同次运行加载 `Droo/2Dtest` 与 `Droo/Atmospheric`,后续有关闭附加层的记录。保存的 XML 中两者均启用且为 Additive;`2Dtest` 的 ambientLight=0.17901662、ambientScatterStrength=2、useOrbitClouds=true;`Atmospheric` 的对应值为 0.0310036615、0、false。XML 只证明保存值,不能替代运行中未保存的调参。

修复前 `build=11 shader=10` 的源码原因(下列行号为当时版本):

- `Clouds.shader:302` 的 ambientScatter 在云步进循环前只计算一次,此时 density=0、transmittance=1,结果恒为零;循环内没有累加此项。调大“环境散射”目前不能恢复夜间云。

- `Clouds.shader:1007` 的 Additive 路径只返回 source.rgb+clouds.rgb,忽略云透射率;有密度但 RGB=0 的云不会改变输入背景。雾合成中的 Additive 分支也只叠加云 RGB。

当时 shader=11 的源码解释两项主要缺口(后续轨道回退见 §16.5):

1. `Clouds.shader:1013` 的 Additive 返回 source.rgb+clouds.rgb。已有透射率 0.003922 表示该采样点本应仅透过约 0.4% 的背景,但该分支对输入背景保持 100%;云的散射颜色仍叠加。图 3 的星空穿厚云与此相符。Standard 可以衰减合成时已有的背景,最终星空遮挡还需核对游戏星空绘制顺序,不能单凭切换模式保证全部修好。
2. `Clouds.shader:294` 的环境入射项在整层为同一 RGB,没有从天空 / 云顶到内部的环境光遮蔽,只经过观察方向的消光累积。高光学厚度时颜色趋于同一个饱和值,与日志中透射率不同、RGB 相近的灰团相符。当前各向同性平均仍乘银边强度;银边设为 3 会放大全局环境项的一部分,无法凭该参数生成真实的夜间定向银边。轨道项也只是覆盖×环境色×细节 albedo,夜侧太阳项归零后没有体积自阴影;其壳面与体积轮廓的差异仍在。云没有独立月光方向 / 强度输入。

图 3 的分散圆块轮廓可以近似积云碎块或破碎层积云,但不能仅凭夜间截图确定云属;灰色或模糊边缘本身不是错误。现实云的明暗取决于天空 / 月光 / 地面等入射来源、光学厚度和照明方向,厚云会遮住其后的发光体。参考 [WMO 云亮度](https://cloudatlas.wmo.int/zh-hans/appearance-of-clouds-luminance.html)、[NOAA 十种基本云](https://www.noaa.gov/jetstream/clouds/ten-basic-clouds)。当前画面可以通过云形联想到真实云,但光照与遮挡还不能作为真实夜云的验收标准。

后续优先核对透射率 / 星空的最终合成契约,再评估环境入射的云内遮蔽及银边与环境项解耦;若要求月光方向性,需独立核对游戏可用光源。云形 / 2D–3D 表示继续按[既有提案](proposals/orbit-transition-antitiling-plan-2026-10-11.md)的先过渡、后反平铺顺序推进;更改曲线不能单独修复壳面缺少体积的问题。上述剩余项尚未实施,不把调暗环境光或调大采样步数当作完整修复。

### 16.5 仅回退 2D 轨道夜光

【决策:2026-10-14】用户要求仅将 2D 轨道云恢复本次夜光改动前的行为,让太空夜侧轨道云不可见。以 §16.2 之前的 `OrbitClouds` 为基线,不扩大为白天禁用轨道云。

`Clouds.shader` 的 `OrbitClouds` 移除 `_CloudAmbientColor` 声明及环境 RGB 项,恢复 `light=lerp(ambientLight,1,ndl)` 与 `col=cloudColor.rgb*light*albedo*coverage*orbitBrightness*dayFactor`。银边继续乘同一个太阳 dayFactor;深夜两项 RGB 均为零。覆盖 / 透射率、宏观分布、浮雕 / albedo、调试输出、2D–3D 淡入与分派保持原实现。当前 Additive 下,纯轨道夜侧不向输入背景添加云色;Standard 仍沿用既有透射率遮挡,未强制改为完全透明。

shader 修订为 12,C# build 保持 12。与本次修改前快照逐字比较,除 `OrbitClouds` 和修订号外其余 shader 内容一致;体积环境散射、反射、雷光与 Composite 未改,C# / 配置 / 用户预设未改。减少轨道项的少量 RGB 运算,没有新增采样、RT、pass 或 CPU 工作。
