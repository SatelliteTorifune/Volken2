## 1. 结论

最值得借鉴的是 **全球覆盖与局部细节分工、与覆盖配套的法线、真实反平铺采样**。KSA 的地球 2D / 3D 共用全球覆盖贴图,2D 使用专门的法线图;体积噪声是有限深度的细节侵蚀,并用三个稳定随机偏移样本打散平铺。它没有把原始 3D 噪声单切片当成整个轨道云的主轮廓。

核对时 Volken 的 mip / 小瓦片平均处理属于过滤与远景简化,后续因镜头抖动撤回动态退场;反平铺是在保留细节时打散重复,两者用途不同。KSA 也没有证明“同一噪声单切片 = 体积积分轮廓”。旧轨道方案 §3-B 对一致性的保证过强,当前宏观表示及其边界以修复文档 §12 为准。

本次参考核对阶段只记录文档,当时版本为 `build=5 shader=4`。后续修改见修复文档 §12~§13,最新 `build=9 shader=8` 补单段积分与输出端重建;既有 152 项与当前 185 项回归均不算 KSA 方案的移植验证。

## 3. 借鉴项与当前缺口

| 优先级 | 可借鉴做法 | Volken 对照 / 落点 | 成本与边界 |
|---|---|---|---|
| 1 | 全局覆盖贴图按导数采样 | 轨道 shape / detail 已过滤,但 `SampleStockDistribution` 和 `PlanetMapTex` 仍固定 mip 0;可先补 SampleGrad / 合适 mip,带经度接缝与极区处理 | Stock cubemap 已有 mip;程序化 PlanetMap 当前无 mip,须先补资源链;各向异性有额外采样成本 |
| 2 | 全局覆盖定主轮廓,局部噪声控制有限侵蚀 | 复用 StockCloudMap / PlanetMap 作共同分布入口,重构当前 `shape×dist + layers + coverage偏置` 的壳面公式,让局部细节不主导整片轨道云 | 需要明确旧 coverage / densityScale / 层强度语义并比较旧预设;共用分布改善宏观衔接,不保证像素级一致 |
| 3 | 与轨道覆盖对应的法线图 | 当前每像素用三份 coverage 求差分,且邻点只是切平面位移;可在分布 / 配置变化时生成每层法线缓存,或先用低频宏观覆盖求球面差分 | 增加一张贴图 / 缓存失效逻辑;可能降低逐像素梯度成本,真实收益待测;法线空间须随云旋转正确变换 |

### 3.1 覆盖和法线最适合当前问题

KSA 地球的 2D 云颜色与法线是配套资源,体积使用相同全球覆盖再生成局部体积细节。这种数据分工同时处理“大轮廓”和“看起来有体积感”,当前仅把噪声变平滑还没有完整实现它。

建议先用当前行星自己的 StockCloudMap;无有效通道时保持程序化分布回退。JNO 源码 `PlanetCubemapUtility.cs:675` / `:690` 创建带 mip 的 cubemap 并 Apply(true,true),可以利用已有资源。通道仍是低 / 中 / 高云与遮罩,不能照 KSA 的 RGBA 颜色 / alpha 定义直接解释。

若给当前程序化 `PlanetMapTex` 补完整 mip:它是 4096×2048 RGFloat,基级理论约 64MiB,新增 mip 理论约 21.3MiB / 云层,不含驱动对齐。不能把这一项与两张 128³ R8 噪声新增约 0.57MiB 混为一谈;可考虑专用较小覆盖缓存或共享分布,须先明确精度与生命周期。

### 3.2 反平铺的适配条件

KSA 做法是球面方向到平面网格、三角形三个顶点的整数 hash 偏移、三份噪声加权。它仍使用周期纹理,但相邻区域的相位不同,从而打散直接可见的重复。

迁移应核对球面两半球 / 网格边界连续性、云空间旋转、行星半径、浮动原点和 shader 平台;KSA 极轴与当前项目约定不同。只在 2D 引入随机相位而 3D 保持旧相位会增加局部形状差异。必须同时决定哪些消费者共用 helper,以及体积 / 光采样预算。

### 3.3 KSA 过渡的实际语义

令 u 为高度带内 0~1 进度,其实际 shader 为:

```text
2D 权重 = clamp(4u, 0, 1)
3D 权重 = clamp(1.33(1-u), 0, 1)
```

约前 25% 已建立完整 2D 云,体积在约 25% 后开始淡出。权重和可接近 2;源码注释说约 33%,但实际 1.33 系数对应约 24.8%,这里以表达式为准。当前项目采用互补 smoothstep 混合;应先校准覆盖 / 亮度和合成契约,再单独评估曲线。

## 4. 原建议推进顺序与验证(已被新提案接管)

1. **先做全球分布过滤**:只动轨道入口,验证经纬接缝、极区、星球边缘、缩放和不同分辨率;检查覆盖 / 平均亮度变化。
2. **再做覆盖与配套法线**:明确每个活跃层的共享分布 / 通道,用相同位置 2D 开 / 关与过渡带检查宏观轮廓;正常太阳 / 晨昏都比较。
3. **需要保留更多非重复细节时做反平铺**:先独立受控对照,测试周期偏移相关性、网格接缝、浮动原点稳定性及每相机 GPU 耗时;共用辅助函数后核对 TSS 的云空间运动。
4. **最后评估体积 mip / 过渡 / flow**:分别测量,不同时改变密度与合成,以便归因。

若追求更接近体积积分的轨道表示,可研究从现有密度场生成列覆盖 / 法线缓存。这是对 Volken 的推导方案,不是本次发现 KSA 在运行时烘焙自身体积云;须先处理参数、风、旋转和噪声变化的失效条件及启动成本。

以上均是提案。本轮没有移植 KSA shader、运行新增 GPU 验证、打包或提交 / 推送。
