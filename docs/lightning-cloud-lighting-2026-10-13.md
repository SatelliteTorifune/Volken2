## 1. 动机与范围

现有 BIRP 云在 `Clouds.shader` 中自行积分光照,落雷点的 Unity `Light` 不会自动进入云的 raymarch。用户选择在有云的观察采样点向闪电光源额外步进,用沿途云密度计算遮光,并于 2026-10-13 授权实施。

【决策:2026-10-13】每帧选一个代表光源,放在当前闪电的云端起点。体积云主视角默认 8 步,水面反射最多 4 步。光源只在亮脉冲内有效,按有限距离积分当前云层的遮光。天气预设存储参数,不修改云预设、密度或高度带。

第一版覆盖主视角、允许的附加相机和已有水面反射体积云。纯 2D 轨道壳没有体积密度积分,本版未接入雷光;过渡带随原体积权重淡出。同一光程只积分当前渲染云层,不累加其他独立 CloudLayer 的遮挡。

## 2. 光照计算

最新实现将有限光程步进放到光源周围固定的 33³ 世界空间格点,每个亮帧、每相机云层生成光学厚度图集。观察射线已有正密度的采样点只插值图集并计算距离衰减,不再嵌套密度步进。格点采用以下遮光计算:

1. 先查闪光是否有效,再以光源半径拒绝范围外的位置。
2. 云端光源与采样点之间的有限线段若穿过行星实体,直接拒绝;光源后方的行星不遮挡它。
3. 将路径终点裁到云层外球面,以固定数量的中点样本覆盖整段路径。复用 `SampleDensityCheap` 和稳定 mip 0,不截取太阳光的固定步进距离。
4. 积分 `tau = sum(max(density, 0) * segmentLength * max(cloudAbsorption, 0))`,光源透过率为 `exp(-tau)`。
5. 格点光学厚度最高为 20,达到该值时早停;超过范围或穿过行星的格点写 20。观察采样点仍检查真实有限行星遮挡,以免插值造成实体漏光。
6. 观察采样点通过两个双线性图集读取及 Z 切片插值得到光学厚度。距离衰减为 `(1 - d²/R²)² / (1 + 25*d²/R²)`,范围外为零,中心亮度有限。
7. 将雷光按无方向偏好的单次散射加入独立 RGB 能量,使用已有单段 Beer 积分权重和观察透过率。散射系数取云吸收系数,使亮度尺度有限。它不受太阳昼夜门控、太阳相函数或 `cloudColor` 调色影响。

已有云 alpha 仍为观察透过率,不会因为雷光而改成不透明。太阳光、云影和密度场继续走原路径,共用密度函数移入 `CloudVolumeLighting.cginc`。固定少量光程样本与空间图集均属于近似:细薄遮挡可能被漏采或平滑;默认 3000m 半径的格点间距为 187.5m,增大半径会降低遮光空间分辨率。

## 3. 闪光状态与缓存

`LightningBolt.TryGetCloudLight` 遍历现有活跃闪电集合,选当前参考系内亮度最高的有效亮脉冲,并提供位置、范围和颜色强度。多个闪电不会增加每个云采样点的光源循环;强度相同时优先最近创建的对象。云光强度乘以该闪电 `flashIntensity / 50`,输出能量上限 1000。

暂停、停用对象、结束、天气 / 雷开关关闭和参考系纪元失效时不再提供云光。主相机与反射每次绘制前分别写入材质,无光时也明确写零,避免共享材质或 clone 残留。

基础云低清颜色、全清上采样及全清历史保持原 ARGB32。开启功能后新增同尺寸低清雷光 ARGBHalf RT,不支持时回退 ARGB32;该 RT 只保存本帧雷光,作为 MRT 3 写出。合成时在基础云时序完成后加入本帧雷光,再应用原轨道过渡、雾与前景权重。开关切换触发 RT 重建,每次亮灭不重新分配;需 GPU 支持至少 4 个 MRT。

雷光不进入基础云历史,无需按光源球域拒绝整份 RGB 历史;首亮、移动与熄灭直接反映本帧,基础云降噪保持。无亮脉冲时明确绑定黑纹理,避免残留。反射独立缓存最多 4 步,直接输出当前雷光与原范围的基础颜色,不重复叠加主视角的雷光 RT。

## 4. 配置与使用

参数位于天气面板的“雷”组,支持中 / 英 / 俄三语及 XML 保存、复制和加载。

| 字段 | 中文面板 | 默认 | 有效范围 |
|---|---|---|---|
| `cloudLightingEnabled` | 闪电照亮云层 | false | 开 / 关 |
| `cloudLightIntensity` | 云内雷光强度 | 8 | 0–100 |
| `cloudLightRange` | 云内雷光范围(米) | 3000 | 1–30000;面板最小 100 |
| `cloudLightSamples` | 云内雷光采样数 | 8 | 2–16;反射最多 4 |

旧 XML 不含这些字段时使用初始化默认值,效果保持关闭。非有限强度 / 半径回退默认值,采样数限制在有效范围。先启用“雷”及“闪电照亮云层”,以 8 步、3000 米开始调整;强度为零时无云光。原落雷点光强度 / 范围继续控制地表 Unity Light,与云端参数独立。

随机闪电起点来自现有云高度带与随机偏移,没有保证起点位于正密度区域。若起点落在空洞,附近没有云或用户云配置关闭,看不到被照亮的云属于当前生成方式的边界。细长放电通道、多光源和多次散射不属于本版。

## 5. 开销

第一版最坏额外密度查询为 `P * M * N`,其中 P 为低清像素数、M 为观察射线光域内正密度采样数、N 为遮光步数。用户复测仍卡顿,§8 已撤回这条嵌套执行路径。最新每个亮帧每相机云层最多 `33³ * N` 次遮光密度查询;主路径默认 8 步约 28.75 万次,反射最多 4 步约 14.37 万次。范围外及饱和光学厚度格点会提前退出,实际查询更少。

观察采样点在光域内至多读取两次光学厚度图集,仍有原观察步进和散射运算。每次廉价密度查询仍包含现有两次 3D 噪声、行星分布、可选 stock cubemap 及高度带运算。光灭时不生成图集、不查询雷光;已分配的低清雷光 RT 和图集保留,不随脉冲分配。多层、多相机按各自路径叠加。

主路径新增低清 HDR 雷光约 `8 * lowW * lowH` 字节,297×132 的 RHalf 图集约 76.6 KiB;RHalf 不支持时图集回退 RFloat。480×270 低清时两者共约 1.06 MiB;不再翻倍全清上采样 / 历史颜色。反射 HDR 颜色另增加 `4 * reflectionW * reflectionH` 字节,并有一个同规格遮光图集。

这些是代码预算与内存尺寸推算,不代表游戏 GPU 毫秒数。真机需比较无闪光帧、亮脉冲峰值、主视角 / 反射、4 / 8 / 16 步,并记录分辨率、实际低清尺寸、可见云层及显卡。

## 8. 用户复测后的闪光开销、云抖动与落点减亮

### 8.1 反馈与证据

用户确认上一轮问题仍在,启用闪电照亮云层后更明显;进一步确认变刺眼的是落点球形闪光。2026-10-13 22:43:29 的游戏日志已经是 `build=10 shader=9`,因此不能把问题归因于旧版未更新。日志中一段平均 148.76ms / 最大 670.14ms,仍有两层云、雾、雨及碰撞;完整游戏负载没有单项 GPU 计时。

另发现 `recenterCount=1299`,最近位置 / 速度变化仅 `1.16415e-10m / 1e-9m/s`,大量 `Δ=0.0m` 通知仍清三个历史 RT。对照 `GameViewScript.RecenterReferenceFrame` 与 `ReferenceFrame.Recenter`,事件在重定位尝试后统一派发,不保证有效的位置变化。该历史清理会打断稳定性并增加全清操作;它不证明游戏自身重定位开销由本模组造成。

### 8.2 最新实施

【决策:2026-10-13】保留向光源额外步进的遮光方法,将其移出观察射线内循环。每相机云层在亮帧生成固定世界空间光学厚度图集,观察采样点只插值。雷光另写 MRT,在 Composite 阶段叠加;基础云颜色格式和历史不随雷光改变。

- `CloudLightningCache` 使用一个 297×132 图集打包 33³ 格点,同一帧同一材质 / 光源 / 步数重复绘制复用;相机旋转、缩放不改变格点。下一亮帧按最新云场重建,不开常驻 GPU 回读。
- `CloudVolumeLighting.cginc` 共用原密度 / 太阳光 / 云积分函数。`LightningShadow` pass 向光源步进,Clouds 观察循环删除雷光密度步进;保持 mip 0、有限路径、行星遮挡和单次散射。
- 主视角基础颜色 / 上采样 / 历史保持 ARGB32,仅本帧雷光为低清 HDR。删除上一光源球域历史拒绝,脉冲不会再把基础云切换到未累计颜色;光灭时当前雷光 RT 清零且合成绑定黑纹理。
- 位置和速度变化均不超过 0.001 时忽略重定位通知,保留真实位移 / 速度跳变及非有限输入的保守历史清理。该过滤只改变模组处理,不修改游戏的参考系。
- 落点球形闪光由 `flashIntensity × 0.4` 改为 `× 0.2`,默认实际强度 20→10,云内雷光强度保持独立。Unity Point Light 参数仍由天气配置控制;组件备用默认值从 8 对齐到配置默认 1,不覆盖已保存的用户值。完整亮灭时间表继续保留。
