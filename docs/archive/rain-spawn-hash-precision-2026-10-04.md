## 0. 现象与结论

现象:雨滴**重复落在同样的地方** —— 落点成簇,看得出"同一处反复在下"。

结论:`RainParticles.compute` 的随机数是 "hash without sine" 的 1D 式:`frac(p*0.1031)` → `p*(p+33.33)` → `2p²` → `frac`。它只对**小输入**有效,而喂进去的是**随粒子下标与时间增长的浮点数**:种子 = `id*7.13+1`(容量 10 万 → 最大 7.1e5),重生再叠上 `floor(_time*20)*7.13`。float32 在做 `frac` 时,输入到 7e4 量级只剩 ~128 级分辨率,越过 2^23 后**恒为 0** → 大量粒子拿到**同一个随机值**,空间分布严重重复。

这不是"雨看起来太整齐"的观感问题,而是**分布本身退化**:10 万粒在 R=50m 的球域里只剩 ~1.3 万个不同落点,最坏一处堆了 655 粒;随时间继续恶化,最终**全部落在同一个点**。

## 1. 判据(离线 float32 复刻;cap=100000、R=50m、落点按 0.1m XZ 格统计)

| `_time`(= `Time.time`,按真实秒增长) | `frac` 级数 | 唯一落点(应有 ~9.3 万) | 单点最多堆多少雨滴 |
|---|---|---|---|
| 0 s(刚进飞行) | 128 | 12,888(12.9%) | 655 |
| 60 s | 128 | 13,232(13.2%) | 351 |
| 1 h | 253 | 2,983(3.0%) | 754 |
| 10 h | 63 | 589(0.6%) | 1,573 |
| 1 d | 8 | 43 | 12,511 |
| ~6.5 d | 1 | 1(**全部同一点**) | 100,000 |

对照(同一套 θ/φ/u 公式,只把 hash 换成 32 位整数):93,252 唯一(93.3%)、最大重复 4 —— 与"10 万点在 R=50m 圆域、0.1m 格"的几何期望 **93.6%** 吻合。也就是说**修前 t=0 就已损失 86% 的空间唯一性**;容量越大越糟(cap=200000:最大重复 1,305 → 1 天 25,012),因为种子与 id 成正比。

**为什么既有诊断看不见**:原来的回读只取**前 64 粒** —— id 最小、`frac` 分辨率最高的一批,实测 64/64 全不同;而重复是**跨 id 区间的混叠**(相距很远的 id 落到同一个量化格),任何连续小样本都正常,必须整块采样。

## 2. 修法(整数 hash:质量与输入量级无关)

| 位置 | 改法 | 为什么 |
|---|---|---|
| `RainParticles.compute` | 删 `Hash11(float)` / `RandomUnitVector(float)`,换成 `HashU(uint)` + `Hash01u(salt, id, phase)` + `SpawnRandom(id, phase, out nd, out u)` | 输入是整数 id 与整数相位,24 位尾数输出;不存在"输入越大越不准" |
| `RainParticles.compute` | 新增 `uint _phase`,相位由 CPU 传(C# `PhaseNow()` = `(uint)floor(_time*20)`) | 相位是 hash 的整数输入;shader 不必再把 `_time` 变成浮点种子 |
| `RainParticles.compute` | `Randomize` 的球域位置与外观 `yzw` 都改走 `Hash01u` | 初始随机化与重生同一条路径,量级无关 |
| `RainParticles.compute` | `RandomSpawnInside(uint id, uint phase)` 取代 `(float seed, float phase)` | 参数即整数,杜绝"以后又把 float 塞进来" |
| `RainParticles.cs` | 加 `_phase` uniform、`PhaseNow()`;heartbeat 增 `time=` / `phase=` | 相位与诊断同源同式,日志可直接对上 shader 的输入 |
| `RainParticles.cs` | 新增**整块** positions 回读的落点分布诊断(每 `DistInterval` = 300s 一次) | 唯一率是这次修复的验收指标,见 §3 / §4 |

**铁律(GPU 侧随机数)**:不许把"随 id / `_time` 增长的浮点输入"喂给 `frac`-hash。要么输入有界(如 `frac` 之后的值),要么直接用整数 hash —— 该路径上任何"种子 = 下标 × 常数 + 时间 × 常数"的写法都会复现本 bug。

## 3. 验收判据

离线(已过;脚本按 shader 逐式用 uint32 复刻):

| 相位 | `t=0` | `t=60s` | `t=1h` | `t=1d` | `t=1年` | `phase=2e9` |
|---|---|---|---|---|---|---|
| 唯一率 | 0.932 | 0.932 | 0.931 | 0.931 | 0.931 | 0.932 |
| 最大重复 | 4 | 5 | 4 | 4 | 4 | 4 |

均匀性:`Hash01u(θ)` 均值 0.4998、10 桶最大偏离均匀 2.6%;`cos(φ)` 均值 −0.0003;`corr(θ,u) = −0.004`;相邻相位落点相关系数 +0.001(去相关)。

真机(已通过):进飞行后 ~20s 打出

```
RainParticles 分布诊断: N=100000 唯一XZ格=93165 唯一率=0.932 最大重复=5 重复≥8 格=0 坏值=0 time=20s phase=390 | 判据 唯一率≥0.90 且 最大重复≤8
```

**唯一率 0.932 / 最大重复 5 —— 判据通过**,与离线预测(`t=0~1 年` 均 0.931~0.932、最大 4~5)逐位吻合,也就是"新 compute 真的在跑"(旧实现同期是 ~0.13 / 数百)。同批日志还确认:4 个 kernel 全部 `FindKernel` 成功、`assets='ok(compute+shader+kernels)'`、`compute写yzw=True`、`shaderVer=7`、绘制 `calls==draws`、无雨相关异常。

仍未取到的样本:该次飞行未暂停时长只到 `time=123s`,不够 5 分钟,所以**只有一次采样**;"唯一率不随时间下降"这条真机只覆盖到 20s(离线扫到 1 年)。要补样本就正常飞 >5 分钟(诊断按真实秒计时,暂停也在计时,但暂停期间 `Time.time` 不走、数据不变,读数会重复)。

读数注意:
- `dist[64]` 那行的 `mean/R≈0.87`(注释写期望 0.75)**不能用来判分布**:它拿"当前相机位置"去量"派发那一刻域中心"的坐标,相机 86 m/s + 异步回读延迟 → 整体偏 ~15~20m(`max=69.7 > R=50`、`beyondR=23` 都是这个偏移),而 shell 重生又抬高了均值。唯一率统计对整体平移不变,不受此影响。
- 日志里 `dt=0.0000` / `respawns=0` / 读数整段重复 = **游戏暂停**(`thunder suspended (game paused)` 可对照),不是 kernel 停摆;恢复后 `respawns` 立刻回到 1.2e5~5e5/10s 量级(kernel 在跑且回收在工作)。

## 4. 验证方法(为什么必须整块回读)

- **整块**:重复来自跨 id 区间混叠,连续小样本看不出(实测尾部 64 粒在 t=0~1h 是 55~64 个不同位置,而整场只剩 1.3 万落点)。
- **对照实验(把根因证死)**:①把 `_time` 钉成 0.5s → 唯一率仍 ~13%(因为 `id*7.13` 本身已到 7e5,"重置时间"修不好);②只把 hash 换成整数 → ~93%。合起来即"精度问题",与 `respawnMirror` / `testRow` / `domainR` 等旁因无关(那三个在 heartbeat 里已有字段可读:面板的露天探针、`domainR=`、配置 `respawnMirror`)。
- **代价**:整块回读 = `cap×16B`(10 万 → 1.6MB),每 5 min 最多一次,不进每帧路径。

## 5. 限制 / 未做

- `respawnMirror = true`(配置项,默认 false,仅作对照)走 `_respawnMode == 1` 的**确定性镜像**分支:那是另一条已知的"零混合 → 周期性成团"路径,不在本次修复范围。
- 旧包里"compute 没写 `_RandomData.yzw`"的 CPU 兜底(`initRnd` / `Hash01`)保留:它管的是**外观**(雨丝长/宽倍率与滚转),与空间分布无关。
- 本次未改雨丝朝向 / 拉伸(那与落点分布正交);PIP 额外相机各跑一份同样的 compute,同样受益。
